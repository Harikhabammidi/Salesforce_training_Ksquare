#  Sprint 01 – Apex Collections, Governor Limits & Asynchronous Processing

##  Overview

In this sprint, I focused on understanding the fundamentals of writing efficient and scalable Salesforce Apex code. I worked with Apex Collections, Governor Limits, bulkification techniques, SOQL best practices, triggers, asynchronous Apex, and Lightning Web Component communication.

The sprint helped me understand how Salesforce handles data processing and why writing optimized and bulk-safe code is important in real-world applications.

---

##  Topics Covered

* Apex Collections – List, Set, and Map
* Salesforce Governor Limits
* Bulkification
* SOQL Best Practices
* Apex Triggers
* Trigger Handler Pattern
* Asynchronous Apex
* `@future` Methods
* Queueable Apex – Introduction
* LWC Parent-to-Child Communication
* LWC Child-to-Parent Communication
* Custom Events in LWC

---

##  What I Learned

* Practiced storing and processing Salesforce records using **Lists, Sets, and Maps**.
* Learned how **Governor Limits** control the amount of resources Apex can use.
* Understood why **SOQL and DML statements should not be placed inside loops**.
* Created and tested an inefficient trigger to understand the problems caused by non-bulkified code.
* Improved the trigger by using **Sets and Maps** to process multiple records efficiently.
* Learned the importance of **bulkification** when working with Salesforce records.
* Implemented an asynchronous Apex process using a **`@future` method**.
* Learned the basic concept of **Queueable Apex** and when asynchronous processing can be useful.
* Practiced passing data from **Parent to Child components** in LWC using `@api`.
* Implemented **Child to Parent communication** using Custom Events.
* Improved my understanding of writing maintainable and reusable Salesforce code.
